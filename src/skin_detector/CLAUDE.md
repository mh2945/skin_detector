# src/skin_detector/ — 어댑터 계층

`core/` 를 바깥세상(파일·카메라·cv2·mediapipe)에 잇는 층이다.
**모바일 포팅 때 여기는 다시 쓰고 `core/` 는 그대로 넘어간다** — 그 경계를 흐리지 않는다.

| 파일 | 역할 | 포팅 |
|---|---|---|
| `pipeline.py` | **유일한 오케스트레이터.** 바깥에서 부르는 진입점은 이것뿐 | 재작성 |
| `face.py` | MediaPipe 어댑터 + 정규 프레임 워프 + manual ROI 폴백 | 재작성 |
| `imageio.py` | 로드 · EXIF · 축소 · store 편입 · JSON 입출력 | 재작성 |
| `render.py` | 히트맵 · 병변 마커 · 부위 외곽선 · contact sheet | 재작성 |
| `core/` | 색 과학 (별도 `CLAUDE.md`) | **그대로** |

## 좌표계는 하나뿐이다

`core/` 안의 모든 좌표는 **정규 프레임(768×768, IPD=320)** 기준이다.

- 원본 → 정규 프레임 변환은 **`face.py` 한 곳에서 한 번만** 일어난다.
- 역변환은 **`pipeline.lesions_to_original()` 하나뿐**이다.
- 원본 좌표는 render/report 만 쓴다.

> 좌표계가 둘인데 규약이 없으면 언젠가 반드시 섞인다. 오버레이가 어긋나는 버그는
> 대부분 여기서 나온다.

## 9:16 고해상도 처리 — 왜 이렇게 복잡한가

입력이 12MP 9:16(약 2268×4032)이다. 그냥 돌리면 세 가지가 동시에 깨진다.

**① 메모리.** 2268×4032 를 float64 로 올리면 배열 **하나가 219MB** 다.
→ **원본은 uint8 로만 다룬다.** 색 연산은 정규 프레임(7MB)에서만 한다.

**② MediaPipe 정확도.** 내부 detector 가 128~192px 텐서로 축소한다. 9:16 을 그대로 넣으면
레터박싱까지 겹쳐 얼굴이 20px 수준이 된다.
→ **긴 변 1536px 로 먼저 축소해서** 랜드마크를 뽑는다.

**③ 디테일 손실.** 그런데 워프까지 축소본에서 하면 병변 디테일이 실제로 사라진다.
→ **랜드마크는 1536px 에서, 워프는 원본 화소에서.**

```
랜드마크 좌표 오차 1px @1536 → 원본 2.6px → IPD 450 대비 0.6%
행렬 추정에는 충분하다.  "행렬은 싸게, 픽셀은 원본에서."
```

**리샘플링은 딱 한 번** — `warpAffine(원본 uint8 → 768×768)`.

## 프레임 밖 화소

세로 사진은 얼굴이 상단에 붙어 crop 이 프레임 밖으로 나가는 일이 흔하다.
**`BORDER_CONSTANT` 로 채우고 유효성 마스크에서 제외한다.**
`BORDER_REPLICATE` 는 **가짜 피부를 만들어 내므로 금지**다.

## mm 환산은 홍채로 한다

성인 홍채 지름은 **11.7 ± 0.5mm 로 개인차가 거의 없다.** IPD 는 58~70mm 로 편차가 크다.
`mm_per_px = 11.7 / iris_diameter_px` → 임상 크기를 그대로 쓸 수 있다.
**IPD 를 자로 쓰지 않는다.**

## 튜닝 캐시

`analyze()` 는 이미 계산된 `FaceObservation` 을 받을 수 있다. 랜드마크·워프를 건너뛰면
색 단계만 **~30ms** 로 재실행되어 `tune.py` 슬라이더가 실시간으로 반응한다.
캐시 없이는 매번 ~105ms 라 튜닝이 고통스럽다.

## 결과에는 버전이 박힌다

`ALGO_VERSION` + `config_hash` 가 모든 결과 JSON 에 들어간다. 없으면 **어떤 설정에서 나온
숫자인지 알 수 없어 수백 번의 튜닝 이력이 통째로 무의미해진다.**

## manual ROI 폴백의 함정

`observation_from_iris_points()` 는 랜드마커 없이 홍채 2점만으로 동작한다. 다만
**매 이미지마다 손으로 찍은 ROI 의 위치 변동이 조명 변동과 뒤섞여 ICC 를 끌어내린다** —
정규화가 실패한 것처럼 보이는 **가짜 FAIL** 이 나온다.
→ 이 경로로 검증할 때는 **같은 이미지에 ROI 를 3회 다시 찍은 "ROI 재현성 ICC" 를 먼저 재고
그 값을 천장으로 삼는다.**
