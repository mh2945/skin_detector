# core/ — 색 과학 코어

**이 디렉터리는 그대로 C++ 로 옮겨 Android/iOS 공유 코어가 된다.** 아래 규칙은 그 사실에서
파생된 것이지 취향이 아니다. 전체 계약은 `docs/CONTRACT.md`, 물리 유도는 `docs/COLOR_SCIENCE.md`.

## 절대 규칙

1. **`numpy` + stdlib 만 import 한다.** `cv2`·`mediapipe`·`PIL`·`fastapi` 금지.
   `test/test_contract.py` 가 AST 로 강제한다. **`cv2` 가 필요해지면 그 기능이 여기서 나가야
   한다** — 예외를 만드는 게 아니라.
2. **numpy 배열과 dataclass 만 주고받는다.** 파일 경로 없음, I/O 없음, 전역 상태 없음.
3. **모든 좌표는 정규 프레임(768×768, IPD=320) 기준이다.** 원본 좌표를 여기서 다루지 않는다.
4. **C++ 로 옮겨쓸 수 있는 스타일.** 반복문에 1:1 대응되는 벡터 연산만. fancy indexing 곡예 금지.
   FFT 대신 누적합 박스 필터를 고른 것도 이 규칙 때문이다.

## 색 과학 — 코드를 고치기 전에 알아야 할 것

- **로그 비율이 픽셀별 음영을 죽이고, 자기참조가 남은 상수 오프셋을 죽인다.**
  실측: 밝기·픽셀별 음영에 1e-5 이내 불변, 조명색은 순수 상수 오프셋.
  ```
  e = D_G - D_R = log10(R/G)   홍반 축
  m = D_B - D_G = log10(G/B)   멜라닌 축
  ```

- **두 색소는 m 의 부호가 반대다.** 헤모글로빈 (Δe=+0.447, Δm=−0.494),
  멜라닌 (Δe=+0.149, Δm=+0.448). 이것이 모반 기각의 유일한 근거다.
  → 병변 cascade 는 **`|dm|` 이 아니라 부호 있는 `dm`** 으로 비교한다.
     `|dm| > |de|` 로 기각하면 **헤모글로빈까지 걸려 진짜 병변을 전부 버린다.**
     (`|−0.494| > 0.447` 이므로 실제로 그렇게 된다 — 테스트로 확인된 실패다.)

- **멜라닌 회귀 β 는 `[0, 0.6]` 으로 클램프한다.** 멜라닌은 e 와 m 을 **같은 방향**으로
  움직이므로 **음수 β 는 물리적으로 멜라닌일 수 없다.** 자유 적합을 허용하면 회귀가
  홍반을 "멜라닌"으로 오인해 통째로 빼버린다 (β 가 −0.41 → −0.86 으로 끌려간다).

- **β 적합 전에 저역통과한다.** `e` 와 `m` 이 G 채널 노이즈를 공유해
  **순수 노이즈만으로 β ≈ −0.5 가 적합된다.**

- **저역통과는 반드시 normalized convolution** — `blur(d·valid)/blur(valid)`.
  그냥 `blur(d)` 를 쓰면 마스크된 화소가 이웃을 끌어내려 눈·입술 주변이 가짜 저홍반이 된다.

- **색도 게이트 공분산에 바닥이 필요하다** (`chroma_min_sigma`). 없으면 균일한 얼굴에서
  적합 가우시안이 임의로 좁아져 **게이트가 병변 자체를 잘라낸다.**

- **정반사는 마스크로만 쓴다.** `C − min(R,G,B)` 보정은 비율을 비선형으로 바꿔버린다.
  정반사는 분광적으로 중립이라 `min(R,G,B)` 상승이 견고한 프록시다.

- **포화 화소는 버린다.** 클리핑되면 채널 비율 정보가 사라진다 — **물리이지 버그가 아니다.**

- **DoG 응답은 정합 블롭 이득 `0.5 − 1/(1+k²) = 0.1491` 로 나눈다.** 그래야 응답이
  블롭 진폭과 같은 log10 단위가 되어 `peak_min_d` 임계값이 `d` 와 같은 자로 잰 값이 된다.

## 게이트 우선순위 (`quality.py`)

**먼저 걸리는 게이트가 이긴다.** 뒤 조건은 평가조차 하지 않는다.

```
NO_FACE → MULTIPLE_FACES → LOW_LANDMARK_CONFIDENCE → LOW_RESOLUTION
→ POSE_OUT_OF_RANGE → FACE_OUT_OF_FRAME → BLURRY → OVEREXPOSED
→ UNDEREXPOSED → NON_UNIFORM_ILLUMINATION
```

순서 자체가 설계다. 근본 원인(얼굴이 없다)이 파생 증상(흐리다)보다 먼저 보고돼야
`web/server.py` 의 안내 문장이 맞아떨어진다 — "고개를 돌리지 마세요"라고 안내해 놓고
사실은 얼굴이 두 명이었다면 사용자는 영영 통과하지 못한다.

**통과해도 metrics 는 기록한다.** 결과 화면의 "근거"가 여기서 나온다.

## null ≠ zero

측정하지 못한 값은 `None` + 명시적 사유 코드다. **`0.0` 이 아니다.**
`0` 을 반환하면 "측정 못 함"이 "아주 정상"으로 둔갑한다 — 이마가 앞머리에 가려졌는데
점수 0(=매우 깨끗)이 나가면 사용자는 그 부위를 안심하고 넘긴다.

`coverage < 0.5` 인 부위는 점수를 `None` 으로 만든다.

## 좌/우 규약

MediaPipe 의 left/right 는 **피사체 기준**이다. 정면 사진에서 피사체의 오른쪽은
이미지의 **왼쪽(작은 x)** 에 나타난다. `RegionId.CHEEK_R` = 피사체 오른쪽 볼 = 이미지 왼쪽.
**`mask.py` 한 곳에서만 정한다** — 확인된 사실이지 추측이 아니다.

## 부위는 서로 배타적이다

`_region_bands()` 는 우선순위 순서(코 → 이마 → 턱 → 우볼 → 좌볼)로 **이미 배정된 화소를
빼면서** 밴드를 만든다. 상수만 맞춰 두면 (`cheek_inner_gap_frac` vs `nose_half_width_frac`)
toml 튜닝 한 번에 다시 겹친다 — 실제로 1893px 겹쳤던 버그다. **구조로 막는다.**

## 임계값은 전부 `config/default.toml` 에

코드에 매직 넘버 금지. `config.py` 의 dataclass 기본값은 toml 의 **사본**이고, 어긋나면
`test_contract.py` 가 깨진다. **오타 난 키는 조용히 무시되지 않고 `ValueError` 다** —
설정을 고쳤는데 안 먹는 상황이 한 번이라도 생기면 그 뒤 모든 튜닝 결과를 믿을 수 없다.
