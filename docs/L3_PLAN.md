# skin_detector L3 — 병변 검출 모델 도입 계획

## Context

`skin_detector`(mh2945)는 학습 데이터 0장으로 동작하는 룰 기반 도구다. `e = log₁₀(R/G)`, `m = log₁₀(G/B)` 두 축으로 헤모글로빈과 멜라닌을 분리하고, DoG 블롭 검출기로 병변을 찾는다. `docs/ROADMAP.md`는 고도화 사다리 L0→L5를 이미 정의해 뒀고, **L3(소규모 지도학습, 병변만)**의 트리거를 "병변 개수 정확도가 요구사항으로 승격될 때"로 못박았다.

첨부된 리뷰 이미지가 그 트리거다. 이마·좌볼·턱에 사람이 빨간 동그라미로 표시한 영역은 전부 시스템이 놓친 병변이고, 이는 `docs/LIMITS.md`가 미리 선언한 실패 모드와 정확히 일치한다:

- **§3-9** — "블롭 검출기에 '병변' 개념이 없다. 붉고 둥근 것을 찾을 뿐이고, **농포의 흰-노란 중심은 붉은 블롭 모델을 능동적으로 파괴한다**"
- **§3-18** — "Δ ≥ 0.10인 아주 강한 병변은 `darkness_reject_dl`(-8.0)에 걸려 색소 병변으로 오인되어 버려진다. 검출에는 하한뿐 아니라 **상한도 있다**"
- **§3-19** — "`peak_min_k`가 극대점 분포에서 잡음을 재서 임계를 올리므로 **병변이 극단적으로 많은 얼굴에서는 검출이 보수적으로 변한다**"

첨부 이미지는 병변이 매우 많고(§3-19 발동), 밀집도가 높으며(§3-18 발동), 농포성 병변이 섞여 있다(§3-9 발동). 즉 **튜닝으로 해결될 문제가 아니라 룰 기반 접근의 원리적 한계**이며, ROADMAP이 예고한 대로 학습 기반으로 넘어갈 시점이다.

> **[편입 시 주석 — 2026-08-28]** 위 세 조항 중 **§3-18(명도 기각)과 §3-19(`peak_min_k` 가
> 병변 많은 얼굴에서 보수적으로 변함)는 2026-08-27 실사진 튜닝에서 이미 손을 댄 지점이다.**
> 이 문서는 GitHub `main` 을 클론해 작성됐고, 그 작업은 당시 커밋되지 않은 상태였으므로
> 반영돼 있지 않다. 명도 기각은 "기각된 후보 70개 중 62개가 dm<0(혈액)"으로 확인돼
> 수정됐고, 잡음 하한에는 `peak_min_texture_k`(피부 질감 항)가 추가됐다.
> **검출 개수는 0개 → 업로드 90 · 웹캠 52~77개로 올라갔다.** (`docs/LIMITS.md` §2 참조)
>
> **그렇다고 L3 근거가 사라지지는 않는다.** 올라간 것은 *개수*이고 **precision/recall 은
> 여전히 _미측정_ 이다** — 정답 라벨이 없기 때문이다. 오히려 그 사실이 이 문서의 결론을
> 강화한다: 라벨이 없으면 룰을 고쳐도 좋아졌는지 알 수 없다. **§3-9(농포의 흰-노란 중심이
> 붉은 블롭 모델을 파괴함)는 그대로 미해결**이며, 이것이 학습 기반으로 넘어가는 핵심 근거다.
> 아래 본문의 성능 서술을 인용할 때는 이 단락을 함께 읽을 것.

목표는 병변 검출 정확도(위치/개수)를 `LIMITS §2`의 L0 기대치 precision 0.4–0.6에서 **L3 목표치 0.7–0.85로 올리는 것**이고, 최종 배포는 온디바이스(모바일)다.

## 먼저: 첨부하신 이미지로 학습할 수 있나

**저 스크린샷 자체는 학습 데이터가 안 된다.** 결과 오버레이(파란/빨간 컨투어)가 픽셀에 구워져 있어 모델이 정답이 아니라 "그려진 선"을 학습한다. 사람이 그린 빨간 동그라미도 마찬가지로 픽셀에 섞여 있다.

**하지만 두 가지로는 지금 즉시 쓸 수 있다:**

| 용도 | 필요한 것 | 가치 |
|---|---|---|
| **부위 단위 약(weak) 라벨** | 빨간 동그라미가 덮은 부위 → `{이마: 트러블 있음, 좌볼: 있음, 턱: 있음}` | 평가셋 라벨로 즉시 사용 가능. `LIMITS §1`의 성공 기준이 부위 단위이므로 형식이 그대로 맞음 |
| **병변 점 라벨** | **원본 사진**(오버레이 없는) + 클릭 라벨 | L3 학습 데이터. 원본이 `data/store/`에 남아 있다면 재라벨링만 하면 됨 |

즉 **"수집"의 대상은 결과 이미지가 아니라 (원본 사진 + 촬영 메타 + 병변 좌표) 세 쌍**이다. `CONTRACT §10`이 원본을 불변으로 잡아둔 덕에 이 구조는 이미 준비돼 있다.

| A. ACNE04 | 가능 | **저자 개별 허가 필요** (xpwu95@163.com) |

배포 타겟이 온디바이스 모바일 제품이므로 이 제약은 실질적이다. 대응:

**가중치 계보를 두 갈래로 분리해 관리한다.**
- **연구 계보** — A+B+C 사전학습 포함. 성능 상한을 알기 위한 것이며 제품에 싣지 않는다
- **상업 계보** — D(자체 수집) + 허가받은 소스만. 제품에 싣는 것은 이쪽뿐이다

Phase 3의 ablation 표가 이 분리의 근거가 된다 — **각 데이터 소스가 성능에 얼마나 기여했는지를 미리 재 두면, 라이선스 때문에 소스를 빼야 할 때 손실을 예측할 수 있다.** 이것이 ablation을 "있으면 좋은 것"이 아니라 필수로 만드는 이유다.

Phase 0에서 **ACNE04 저자에게 문의 메일을 즉시 발송**한다. 회신에 시간이 걸리므로 가장 먼저 보낸다. 허가가 나오면 상업 계보에 A를 포함시킬 수 있고, 안 나와도 연구 계보로 성능 상한은 확인할 수 있다.

### 경로에서 제외를 권장하는 것

**AI-Hub 피부질환 임상 데이터(106,776장, `dataSetSn=230`)** — 라벨 품질은 최고(바운딩박스 + 세그멘테이션 + 32종 질환, 여드름 10,207건)지만 **오프라인 안심존 접근 전용이라 다운로드가 불가능하고 IRB 승인이 필수**다. 지정된 물리적 공간에서만 분석할 수 있어 온디바이스 모델 학습·반복 실험 워크플로우와 맞지 않는다. 향후 임상 등급(ROADMAP L5) 논의가 생기면 그때 재검토한다.

### 트랙 C가 자체 수집을 상당 부분 대체한다

ROADMAP L3은 "얼굴 300~500장 클릭 라벨"을 요구하는데, 트랙 C는 **한국인 실사진 13,936장을 이미 확보된 상태로 제공**한다. 라벨이 우리가 원하는 형태가 아닐 뿐 이미지 자체는 재라벨링 가능하다. 자체 수집(트랙 D) 300~500장을 몇 주에 걸쳐 모으는 대신, 트랙 C에서 조건에 맞는 이미지를 골라 라벨링하면 훨씬 빠르다.

**단 트랙 D는 여전히 필수이고, 상업화를 고려하면 우선순위가 가장 높다.** 우리 촬영 프로토콜(수동 WB·ISO 고정, 파일명 규약, 편광/플래시쌍)로 찍힌 사진은 트랙 C에 없고, `LIMITS §3-14`가 "성능 수치는 경로 B(업로드)에서만 나온다"고 못박았기 때문에 **최종 판정용 평가셋은 반드시 자체 수집이어야 한다.**

## 라벨 규약

### 좌표계 — 원본 좌표로 저장한다

정규 프레임(768×768, IPD=320) 좌표로 저장하지 **않는다.** `face.py`의 랜드마커 버전이나 정규 프레임 정의가 바뀌면 저장된 라벨이 전부 무효가 되기 때문이다. `CONTRACT §10`이 원본을 불변으로 잡은 것과 같은 논리다.

- 저장: 원본 픽셀 좌표
- 학습 시점: `face.py`의 기존 워프로 정규 프레임에 투영 (`CONTRACT §3` 준수 — 변환은 여전히 `face.py` 한 곳)
- 역변환: `pipeline.lesions_to_original()` 그대로 재사용

### 저장 위치

`data/labels/<labeler>/<capture_id>.json` — `data/store/`는 `CONTRACT §10`에 의해 쓰기 전용이므로 별도 레이어로 분리한다.

**라벨러별로 폴더를 나눈다.** `LIMITS §1`이 평가셋을 "평가자 3명이 독립적으로 매긴 다수결"로 정의했으므로, 한 경로에 덮어쓰면 독립성이 사라져 천장(평가자 간 일치율)을 잴 수 없다.

```json
{
  "image_id": "s01_window_5500_100_torch_1",
  "labeler": "mh",
  "label_version": "v1",
  "lesions": [
    {"x": 1204, "y": 883, "type": "papule", "confidence": "certain"},
    {"x": 1150, "y": 940, "type": "pustule", "confidence": "unsure"}
  ],
  "regions": {"forehead": "trouble", "cheek_l": "trouble", "cheek_r": "clean",
              "nose": "unlabelable", "chin": "trouble"}
}
```

`regions` 값은 `clean` | `trouble` | `unlabelable` 3값이고 **기본값은 `unlabelable`**이다. 별도 `unlabelable` 배열을 두지 않는다 — 상태가 두 곳에 있으면 갈라진다(`CONTRACT §7`). 기본값이 `clean`이면 **라벨러가 보지도 않은 부위가 "깨끗함"으로 학습된다**(`CONTRACT §4`).

- **점 라벨**(중심 좌표)만 찍는다. 박스·마스크는 찍지 않는다 — ROADMAP이 "세그멘테이션 아님, 점만 찍으면 되므로 빠르다"고 지정한 그대로다.
- `type`은 기록만 하고 **v1 모델은 학습에 쓰지 않는다.** `LIMITS §3-1`이 "활성 염증 vs PIE는 원리적으로 구분 불가"라고 선언했으므로, 타입 세분화는 이 계획의 범위 밖이다. 나중에 필요해지면 이미 쌓인 라벨을 쓴다.
- `confidence: "unsure"`는 학습에서 제외하되 평가에서는 "맞아도 틀려도 무관" 영역으로 처리한다.
- `unlabelable`은 앞머리·수염·안경으로 가려졌거나 아직 판단하지 않은 부위. `CONTRACT §4`의 "null ≠ zero"를 라벨에도 적용한다 — 가려진 부위를 "병변 0개"로 학습시키면 안 된다.

### 라벨러 배정

| 데이터 | 라벨러 | 근거 |
|---|---|---|
| 학습셋 | 1인 + 10% 스팟 체크 | 비용 |
| **평가셋** | **3인 독립 + 다수결** | `LIMITS §1` — "평가자 3명이 독립적으로 매긴 다수결, 시스템 출력은 보여주지 않는다(앵커링 방지)" |

평가셋 라벨링 전에 **평가자 간 일치율을 먼저 잰다.** `LIMITS §1`의 "천장" 규정 — 사람끼리 75%면 시스템이 그걸 넘는 건 무의미하다.

## 모델 설계

### 아키텍처: CenterNet 스타일 keypoint heatmap + MobileNetV3-Small

ROADMAP이 지정한 "얼굴 크롭 대상 소형 anchor-free 검출기(FCOS/CenterNet + MobileNetV3)"를 따른다. 박스가 아니라 **점 히트맵**으로 가는 이유:

- 우리 라벨이 점이다. 박스 회귀 헤드를 붙이면 학습할 정답이 없다.
- ACNE04는 박스지만 중심점으로 변환하면 그대로 쓸 수 있다(역방향은 불가능).
- 병변 크기는 기존 `core/measure.py`가 이미 mm 단위로 잘 재고 있다 — 홍채 지름 11.7mm를 자로 쓰는 로직. 모델이 위치만 주면 크기는 룰 기반이 채운다.

**입력 해상도와 stride**: 정규 프레임 768×768, IPD=320px ≈ 63mm이므로 1mm ≈ 5px. `LIMITS §2`의 최소 검출 목표 2–3mm = 10–15px. **stride 4 출력**(192×192)이면 3mm 병변이 3~4셀을 덮어 안정적으로 검출된다. stride 8은 여유가 없다.

### 입력 채널: RGB 3 + ΔEI 1 + Δm 1 = 5채널

ROADMAP의 지시 그대로다 — "색 정규화·마스킹·품질 게이트를 그대로 전처리로 쓰고 ΔEI 맵을 **추가 입력 채널**로 넣는다. RGB만 넣는 것보다 데이터 효율이 좋다."

- `core/measure.py`가 이미 계산하는 e/m 편차 맵을 재사용한다. 새로 구현하지 않는다.
- 사전학습 가중치 이식: 첫 conv를 5채널로 확장하고 RGB 3채널은 ImageNet 가중치 유지, 신규 2채널은 0으로 초기화한다.
- **이것이 L0가 버려지지 않는 지점이다.** 조명 불변 표현이 입력에 이미 들어 있으므로 모델이 조명 불변성을 데이터로 처음부터 배울 필요가 없다 — 300~500장 규모에서 결정적이다.

### 얼굴 마스크 적용

`core/mask.py`의 5부위 마스크를 그대로 써서 눈·눈썹·입술·콧구멍·머리카락을 학습·추론 양쪽에서 제외한다. `LIMITS §3-9`가 지적한 오검출 원인 상당수가 여기서 사라진다.

### 학습 순서

```
1) ACNE04 (박스→중심점 변환, 1,457장)           사전학습, RGB 3채널
2) + AI-Hub 합성 (12,000장, 마스크→중심점)       사전학습 보강 ※합성 갭 주의
3) + AI-Hub 한국인 실사진 재라벨 (300~500장)     5채널로 확장 후 파인튜닝
4) + 자체 수집 (트랙 D)                          최종 파인튜닝 + 홀드아웃 평가
```

단계마다 평가셋 성능을 기록한다. 단계가 성능을 **떨어뜨리면 그 단계를 뺀다** — 특히 2)의 합성 데이터는 도메인 갭이 클 수 있어 무조건 넣지 않는다.

## CONTRACT와의 충돌, 그리고 해소

`docs/CONTRACT.md`는 "협상 불가"로 선언돼 있고 `test/test_contract.py`가 1·5·9번을 AST로 강제한다. 신경망 도입은 몇 가지와 정면 충돌하므로 미리 정리한다.

| 조항 | 충돌 | 해소 |
|---|---|---|
| **§1** `core/`는 numpy+stdlib만 | `onnxruntime`/`torch`가 필요 | **`core/`에 넣지 않는다.** 새 모듈 `src/skin_detector/lesion_net.py`(core 밖)에 추론을 두고 `pipeline.py`가 조율한다. CONTRACT가 명시한 "cv2가 필요해지면 그 기능이 core/ 밖으로 나가야 한다, 예외를 만드는 게 아니라"를 그대로 적용 |
| **§5** 모든 임계값은 toml | 모델 score threshold, NMS 반경 | `config/default.toml`에 `[lesion_model]` 섹션 신설: `enabled`, `score_threshold`, `nms_radius_mm`, `model_path`, `model_sha256` |
| **§4** null ≠ zero | 모델 로드 실패 시 | 병변 리스트를 `[]`가 아니라 `None` + 사유 코드 `model_unavailable`로 반환. 빈 배열은 "깨끗한 피부"를 뜻하므로 섞이면 안 된다 |
| **§6** C++ 이식 가능 스타일 | 학습 코드는 이식 대상이 아님 | 학습 코드는 `train/`(신규, 저장소 최상위)에 격리. `core/`·`lesion_net.py`는 이식 대상이지만 추론은 ONNX 런타임 호출 한 줄이라 이식 부담이 없다 |
| **§7** 과설계 금지 | 룰/모델 이중 경로 | 추상 인터페이스를 만들지 않는다. `config`의 `lesion_model.enabled` 플래그 하나로 분기하고, 룰 기반 블롭 검출은 **fallback으로 남긴다**(모델 미탑재 환경 대응) |
| **§8** `model/`은 Alchera FaceSDK 폴더 | 이름 충돌 | 신규 가중치는 `assets/lesion/`에 둔다. `model/`은 건드리지 않는다 |
| **§10** `data/store/` 불변 | 라벨 저장 | `data/labels/`로 분리 (위 참조) |

`reprocess.py`의 `algo_version` + `config_hash` 규약은 그대로 유지된다 — 모델 버전과 가중치 해시를 `algo_version`에 포함시키면 **"모델을 바꿨을 때 판정이 뒤집힌 이미지 수"를 기존 도구로 그대로 잴 수 있다.**

### Phase 0 — 착수 (1주)

2. **AI-Hub 신청 2건 제출** — `dataSetSn=71863`(합성), `dataSetSn=71645`(한국인 실사진). 내국인 계정 필요. **샘플 데이터로 라벨 스키마를 먼저 확인**한 뒤 본 신청
3. **자체 수집 동의서·프로토콜 확정** — 아래 개인정보 섹션 참조
4. **현황 파악** — `data/store/`에 실제로 몇 장이 있고 촬영 메타가 붙어 있는지 확인

**산출**: 데이터 접근 상태표 1장. 각 트랙의 실제 라벨 스키마(신청 전 샘플 확인 결과 포함)

### Phase 1 — 라벨링 도구와 평가셋 (1~2주)

**학습셋보다 평가셋이 먼저다.** 평가셋 없이 학습하면 결과를 해석할 수 없다.

1. `scripts/label.py` 구현 — ROADMAP이 "이 시점에 추가한다, 지금 만들지 않는다"고 유예해 둔 그 도구. 요구사항: 원본 이미지 위 클릭 → 점 추가, 부위 판정 토글, `unlabelable` 지정, 위 JSON 스키마로 저장. 오버레이 없는 원본만 띄운다(앵커링 방지)
2. **평가셋 40~60장 라벨링** — 3인 독립 다수결. **평가자 간 일치율을 먼저 측정**해 천장을 확인
3. `validate.py`에 `lesion-pr` 서브커맨드 추가 — 거리 기반 매칭 PR 곡선

**Go/No-Go**: 평가자 간 병변 일치율이 너무 낮으면(예: F1 < 0.5) 라벨 정의 자체를 다시 잡는다. 사람도 합의 못 하는 대상은 모델이 배울 수 없다.

### Phase 2 — ACNE04 베이스라인 (2주) ★ 첫 판정 지점

1. ACNE04 박스 → 중심점 변환, `face.py`로 정규 프레임 워프
2. CenterNet + MobileNetV3-Small, RGB 3채널로 학습
3. **평가셋(Phase 1)에서 기존 L0 룰 기반과 직접 비교**

**Go/No-Go 게이트**:
- 우리 평가셋에서 **L0 대비 F1이 개선되지 않으면 중단하고 원인 분석**한다. 도메인 갭인지(→ 트랙 C 우선), 라벨 정의 불일치인지(→ Phase 1 회귀), 아키텍처 문제인지 구분한다.
- ACNE04 자체 홀드아웃 F1이 0.6 미만이면 학습 파이프라인 자체에 버그가 있다고 보고 모델링을 진행하지 않는다.

이 게이트가 중요한 이유: **도메인 갭이 얼마나 큰지를 데이터 수집에 몇 주를 쓰기 전에 알 수 있다.**

### Phase 3 — 5채널 확장 + 한국인 데이터 파인튜닝 (2~3주)

1. `core/measure.py`의 e/m 편차 맵을 학습 파이프라인에 연결, 입력 5채널 확장
2. AI-Hub 트랙 C에서 조건 부합 이미지 선별(정면, 얼굴 크기, 메이크업 없음) → 300~500장 라벨링
3. 파인튜닝, 채널 확장 전후 ablation 기록
4. AI-Hub 합성 데이터(트랙 B) 추가 여부를 성능으로 판단

**산출**: ablation 표 — RGB 3ch vs 5ch, ACNE04만 vs +한국인, ±합성

### Phase 4 — 자체 데이터 최종 파인튜닝과 판정 (1~2주)

1. 트랙 D 자체 수집분으로 최종 파인튜닝
2. `LIMITS §2` 표의 "병변 precision (실사진)" 행을 **실측값으로 채운다** — 현재 `_미측정_`
3. 병변 검출 결과를 부위 판정으로 집계해 **기존 L0 대비 부위 일치율·κ 개선을 측정**. `LIMITS §1`이 요구한 3값(일치율 / NIR / Cohen's κ)을 함께 보고
4. `reprocess.py --compare`로 판정이 뒤집힌 이미지 수 산출

**PASS 기준** (`LIMITS §2` L3 목표치 기준):
- 병변 precision ≥ 0.7, recall ≥ 0.6 (자체 수집 홀드아웃)
- 부위 트러블 축 κ가 L0 대비 개선
- 첨부 이미지 같은 **고밀도 병변 케이스에서 검출이 무너지지 않을 것** (§3-19 회귀 테스트)

### Phase 5 — 온디바이스 포팅 (2주)

1. ONNX export → TFLite(Android) / CoreML(iOS) 변환, INT8 양자화
2. 양자화 전후 정확도 손실 측정. 손실이 크면 FP16으로 후퇴
3. `lesion_net.py`를 C++로 이식 — 추론 호출만이므로 부담이 작고, `core/`의 전처리·후처리는 ROADMAP이 예고한 대로 **그대로 넘어간다**
4. 지연 시간 측정 — 목표 10~20ms(ROADMAP 명시치)

## 개인정보 처리 (트랙 D)

얼굴 이미지는 개인정보보호법상 **민감정보(생체인식정보)**에 해당하며, 일반 개인정보 동의와 **별도로** 동의를 받아야 한다.

- **별도 동의서** — 수집 목적, 수집 항목(얼굴 이미지·촬영 메타), 보유·이용 기간, 파기 방법, **동의 거부 권리와 거부 시 불이익 없음**을 명시
- **사내 수집의 자발성** — 근로자 대상 수집은 동의의 자발성이 쟁점이 된다. 참여/불참을 인사 정보와 분리하고, 불참에 불이익이 없음을 문서로 남긴다
- **가명처리로는 부족하다** — 얼굴 이미지 자체가 식별자라 메타데이터를 지워도 익명화되지 않는다. 원본은 로컬 암호화 저장 + 접근 통제로 관리하고 외부 반출하지 않는다
- **AI-Hub 상업적 이용** — AI-Hub 데이터는 명시적 승인 없이는 상업적 이용이 불가하며 수행기관과 별도 협의가 필요하다. **PoC 단계에서는 연구 목적으로 신청하되, 상업화 논의가 생기는 시점에 반드시 재검토**한다. 이 제약이 트랙 D(자체 수집) 확대의 실질적 근거가 된다
- **온디바이스 배포가 이 문제를 근본적으로 줄인다** — README가 이미 "사진은 이 컴퓨터 밖으로 나가지 않는다"를 강조하고 있고, 모바일 온디바이스는 그 속성을 그대로 유지한다

참고: [생체정보 보호 안내서(개인정보보호위원회)](https://www.data.go.kr/data/15142329/fileData.do), [개인정보 처리 통합 안내서 2025.7](https://www.pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=D010030000)

## 검증 방법

```bash
# 1. 라벨링 도구 동작
python scripts/label.py data/store/<image_id>
#    → data/labels/<image_id>.json 생성, 원본 좌표로 저장 확인

# 2. 평가자 간 일치율 (천장 측정) — 모델 학습 전에 먼저
python scripts/validate.py agreement --labelers mh,a,b
#    → 일치율 / NIR / Cohen's κ 세 값 동시 출력 (LIMITS §1)

# 3. 병변 검출 PR 곡선 — L0 vs L3 직접 비교
python scripts/validate.py lesion-pr --eval-set data/labels/eval --compare-rule
#    → precision/recall/F1, 매칭 거리 임계별

# 4. 판정 뒤집힘 — 기존 도구 그대로 재사용
python scripts/reprocess.py --all
python scripts/reprocess.py --compare v0.2.0_<hash> v0.3.0_lesionnet_<hash>

# 5. 고밀도 병변 회귀 테스트 (첨부 이미지 케이스)
pytest test/test_lesion_net.py -k dense
#    → LIMITS §3-19가 예고한 "보수적으로 변함"이 재발하지 않는지

# 6. 온디바이스 지연 시간
python train/export.py --format tflite --quantize int8
#    → 양자화 전후 F1 손실, 실기기 추론 시간 (목표 10~20ms)
```
