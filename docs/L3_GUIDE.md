## 1. 왜 이걸 하나

현재 `skin_detector` 는 **학습 데이터 0장**으로 도는 룰 기반 도구다. `e = log₁₀(R/G)`,
`m = log₁₀(G/B)` 두 축으로 헤모글로빈과 멜라닌을 분리하고 DoG 블롭 검출기로 병변을 찾는다.

리뷰에서 나온 실패 사례(이마·좌볼·턱의 병변을 통째로 놓침)는 **튜닝으로 해결되는 문제가
아니다.** `docs/LIMITS.md` 가 이미 원리적 한계로 선언해 둔 것들이 동시에 터진 결과다:

| 조항 | 내용 | 그 사진에서 |
|---|---|---|
| §3-9 | 블롭 검출기에 "병변" 개념이 없다. **농포의 흰-노란 중심이 붉은 블롭 모델을 능동적으로 파괴한다** | 농포성 병변 혼재 |
| §3-18 | Δ ≥ 0.10 인 강한 병변은 `darkness_reject_dl` 에 걸려 색소 병변으로 오인돼 버려진다. **검출에 상한이 있다** | 진한 병변 밀집 |
| §3-19 | `peak_min_k` 가 극대점 분포에서 잡음을 재므로 **병변이 극단적으로 많은 얼굴에서 임계가 올라가 보수적으로 변한다** | 병변 수가 매우 많음 |

> **[편입 시 주석 — 2026-08-28]** 위 세 조항 중 **§3-18(명도 기각)과 §3-19(`peak_min_k` 가
> 병변 많은 얼굴에서 보수적으로 변함)는 2026-08-27 실사진 튜닝에서 이미 손을 댄 지점이다.**
> 이 문서는 GitHub `main` 을 클론해 작성됐고, 그 작업은 당시 커밋되지 않은 상태였으므로
> 반영돼 있지 않다. 명도 기각은 "기각된 후보 70개 중 62개가 dm<0(혈액)"으로 확인돼
> 수정됐고, 잡음 하한에는 `peak_min_texture_k`(피부 질감 항)가 추가됐다.
> **검출 개수는 0개 → 업로드 90 · 웹캠 52~77개로 올라갔다.** (`docs/LIMITS.md` §2 참조)
>
> **그렇다고 L3 근거가 사라지지는 않는다.** 올라간 것은 *개수*이고 **precision/recall 은
> 여전히 _미측정_ 이다** — 정답 라벨이 없기 때문이다. 오히려 그 사실이 이 문서의 결론을
> 강화한다: 라벨이 없으면 룰을 고쳐도 좋아졌는지 알 수 없다. **§3-9(농포의 흰-노란 중심이
> 붉은 블롭 모델을 파괴함)는 그대로 미해결**이며, 이것이 학습 기반으로 넘어가는 핵심 근거다.
> 아래 본문의 성능 서술을 인용할 때는 이 단락을 함께 읽을 것.

`docs/ROADMAP.md` 가 정의한 고도화 사다리 L0→L5 중 **L3(소규모 지도학습, 병변만)** 의
트리거는 "병변 개수 정확도가 요구사항으로 승격될 때"다. 지금이 그 시점이다.

**목표** — 병변 precision 을 L0 기대치 0.4–0.6 에서 **0.7–0.85** 로. 배포는 온디바이스(모바일).

## 2. ⚠ 먼저 알아야 할 것 — 저 결과 이미지는 학습 데이터가 아니다

리뷰에 돌던 **결과 오버레이 스크린샷은 학습에 쓸 수 없다.** 파란/빨간 컨투어가 픽셀에
구워져 있어 모델이 정답이 아니라 "그려진 선"을 학습한다. 사람이 그린 빨간 동그라미도 마찬가지다.

**수집해야 하는 것은 결과 이미지가 아니라 세 쌍이다:**

```
원본 사진 (오버레이 없는)  +  촬영 메타 (capture.json)  +  병변 좌표 (라벨)
```

단, 빨간 동그라미가 덮은 **부위 정보**는 약(weak) 라벨로 즉시 쓸 수 있다 —
`{이마: 트러블, 좌볼: 트러블, 턱: 트러블}`. LIMITS §1 의 성공 기준이 부위 단위라 형식이 맞는다.

## 3. ⚠ 라이선스 — 상업 배포에 쓸 수 있는 데이터는 자체 수집뿐이다

**이게 이 프로젝트에서 가장 중요한 제약이다.**

| 트랙 | 규모 | 병변 좌표 라벨 | 연구·PoC | **상업 배포** |
|---|---|---|---|---|
| **A. ACNE04** | 1,457장 | 있음 (전문의 박스) | 가능 | **저자 개별 허가 필요** |
| **B. AI-Hub 안면부 합성** (`71863`) | 12,000장 (합성) | 있음 (마스크 5,000) | 가능 | 수행기관 별도 협의 |
| **C. AI-Hub 한국인 피부상태** (`71645`) | 13,936장 (실사진) | **없음** | 가능 | 수행기관 별도 협의 |
| **D. 자체 수집** | 목표 300~500장 | 우리가 라벨링 | 가능 | **제약 없음** |

**ACNE04 는 CC BY 4.0 이 아니다.** 원본 배포처 [xpwu95/LDL](https://github.com/xpwu95/LDL) 의 조건은:

> ATTN: This work is free for academic usage. For other purposes, please contact Xiaoping Wu (xpwu95@163.com).

Roboflow 등에 올라온 "CC BY 4.0" 표기는 **제3자 재업로더가 붙인 것**이고 원저작자 조건이 아니다.
검색으로 확인하면 CC BY 4.0 이라고 나오므로 반드시 원본을 봐야 한다.

**대응 — 가중치 계보를 두 갈래로 관리한다:**
- **연구 계보** : A+B+C 사전학습 포함. 성능 상한을 알기 위한 것이며 **제품에 싣지 않는다**
- **상업 계보** : D + 허가받은 소스만. 제품에 싣는 것은 이쪽뿐

그래서 **Phase 3 의 ablation 은 선택이 아니라 필수**다. 소스별 기여도를 미리 재 둬야
라이선스 때문에 소스를 빼야 할 때 손실을 예측할 수 있다.

### 경로에서 뺀 것

**AI-Hub 피부질환 임상 (`dataSetSn=230`, 106,776장)** — 라벨 품질은 최고(박스+세그멘테이션,
여드름 10,207건)지만 **오프라인 안심존 전용이라 다운로드가 불가능하고 IRB 승인이 필수**다.
지정된 물리 공간에서만 분석 가능해 온디바이스 학습·반복 실험과 맞지 않는다.

### 트랙 C 의 진짜 용도

`71645` 는 **병변 좌표 라벨이 없다** — 수분·탄력·색소침착·모공 등급뿐이다.
따라서 **라벨 소스가 아니라 한국인 실사진 이미지 소스**로 쓰고, 우리가 재라벨링한다.

## 4. 지금까지 한 일

### 4.1 `scripts/label.py` — 병변 점 라벨링 도구 (신규)

ROADMAP 이 "이 시점에 추가한다, **지금 만들지 않는다**" 고 유예해 둔 그 도구다.

설계에서 양보하지 않은 네 가지:

1. **원본 좌표로 저장한다.** 정규 프레임(768×768, IPD=320)으로 저장하면 `face.py` 의
   랜드마커 버전이 바뀌는 순간 **이미 찍은 라벨이 전부 무효가 된다.** 라벨은 사람의 시간이
   들어간 자산이고 알고리즘보다 오래 살아야 한다. 정규 프레임 투영은 학습 시점에 한다.
2. **라벨러별로 폴더를 나눈다.** `data/labels/<labeler>/<capture_id>.json`.
   LIMITS §1 이 평가셋을 "3명이 독립적으로 매긴 다수결"로 정의했다. 한 파일에 덮어쓰면
   독립성이 사라져 천장(평가자 간 일치율)을 잴 수 없다.
3. **결과 오버레이를 절대 띄우지 않는다.** LIMITS §1 의 앵커링 방지.
   이 스크립트는 `pipeline` 을 **import 조차 하지 않는다** — 구조로 강제했다.
4. **부위 기본값이 `clean` 이 아니라 `unlabelable` 이다.** 계약 4번(null ≠ zero).
   기본값이 `clean` 이면 라벨러가 보지도 않은 부위가 "깨끗함"으로 학습되고,
   앞머리에 가린 이마가 정상 피부의 근거로 쓰인다.

## 6. 라벨링 도구 사용법

```bash
# store 전체 순회
.venv/bin/python scripts/label.py --labeler mh

# 아직 안 찍은 것만
.venv/bin/python scripts/label.py --labeler mh --only-unlabeled

# 파일 하나만 (store 를 거치지 않는다)
.venv/bin/python scripts/label.py --labeler mh --image some.heic
```

| 조작 | 동작 |
|---|---|
| 좌클릭 | 병변 추가 (certain) |
| shift + 좌클릭 | 병변 추가 (unsure — 학습에서 제외, 평가에서 무시) |
| 우클릭 | 가장 가까운 병변 삭제 |
| `t` | 마지막 병변의 type 순환 (none → papule → pustule → comedone → pih) |
| `1`~`5` | 부위 순환 `clean` → `trouble` → `unlabelable` |
| `s` / `n` / `b` / `q` | 저장 / 다음 / 이전 / 종료 |

확대·이동은 matplotlib 툴바를 쓴다. **툴바가 켜져 있으면 클릭은 라벨로 안 잡힌다**(줌 할 때마다 점이 찍히는 것 방지).

> **좌/우는 피사체 기준이다.** 정면 사진에서 피사체의 **오른쪽 볼(`cheek_r`)은 화면 왼쪽**에
> 나타난다. UI 에 힌트를 띄워 두었지만, 이 규약을 모르면 라벨러는 반드시 뒤집어 찍는다.
> 그 오염은 학습이 끝난 뒤에야 드러난다.

### 라벨 스키마

```json
{
  "schema_version": 1,
  "capture_id": "20260827_190300_a1b2c3d4",
  "source_name": "s01_window_5500_100_torch_1.heic",
  "image_size": [4032, 3024],
  "labeler": "mh",
  "label_version": "v1",
  "labeled_at": "2026-08-28T01:53:00+00:00",
  "lesions": [
    {"x": 1204.0, "y": 883.0, "type": "papule", "confidence": "certain"}
  ],
  "regions": {"forehead": "trouble", "cheek_l": "trouble", "cheek_r": "clean",
              "nose": "unlabelable", "chin": "trouble"}
}
```

- 좌표는 **원본 픽셀 기준**
- `type` 은 기록만 하고 **v1 모델은 학습에 쓰지 않는다** (LIMITS §3-1: 활성 염증 vs PIE 는
  원리적으로 구분 불가). 필드는 남겨 나중에 쓴다
- `regions` 3값 중 **기본값은 `unlabelable`**. 별도 `unlabelable` 배열을 두지 않는다 —
  상태가 두 곳에 있으면 갈라진다 (계약 7번)

### 라벨러 배정

| 데이터 | 라벨러 | 근거 |
|---|---|---|
| 학습셋 | 1인 + 10% 스팟 체크 | 비용 |
| **평가셋** | **3인 독립 + 다수결** | LIMITS §1 |

## 7. 모델 설계 요약

**CenterNet 스타일 keypoint heatmap + MobileNetV3-Small, stride 4**

- **왜 점 히트맵인가** — 우리 라벨이 점이다. 박스 회귀 헤드를 붙이면 학습할 정답이 없다.
  ACNE04 는 박스지만 중심점으로 변환하면 쓸 수 있다(역방향은 불가). 병변 **크기**는
  `core/measure.py` 가 이미 홍채 11.7mm 를 자로 써서 mm 로 잘 재고 있다 — 모델이 위치만
  주면 크기는 룰 기반이 채운다.
- **왜 stride 4 인가** — 정규 프레임 IPD 320px ≈ 63mm 이므로 1mm ≈ 5px.
  최소 검출 목표 2–3mm = 10–15px. stride 4(192×192 출력)면 3mm 병변이 3~4셀을 덮는다.
  **stride 8 은 여유가 없다.**
- **입력 5채널** = RGB 3 + ΔEI 1 + Δm 1. ROADMAP 지시 그대로다.
  `core/measure.py` 가 이미 계산하는 e/m 편차 맵을 재사용한다(새로 구현하지 않는다).
  **조명 불변 표현이 입력에 이미 들어 있으므로 모델이 그걸 데이터로 처음부터 배울 필요가
  없다** — 300~500장 규모에서 결정적이다. 첫 conv 를 5채널로 확장하고 RGB 는 ImageNet
  가중치 유지, 신규 2채널은 0 초기화.
- **`core/mask.py` 의 5부위 마스크**를 학습·추론 양쪽에 적용해 눈·눈썹·입술·콧구멍·머리카락 제외.

### 학습 순서


## 8. CONTRACT 와의 충돌 — 미리 정리해 둔 해소안

`docs/CONTRACT.md` 는 "협상 불가"로 선언돼 있고 `test/test_contract.py` 가 1·5·9번을
AST 로 강제한다. 신경망 도입은 몇 가지와 정면 충돌한다.

| 조항 | 충돌 | 해소 |
|---|---|---|
| **§1** `core/` 는 numpy+stdlib 만 | `onnxruntime` 필요 | **`core/` 에 안 넣는다.** `src/skin_detector/lesion_net.py`(core 밖)에 추론을 두고 `pipeline.py` 가 조율. CONTRACT 가 명시한 "그 기능이 core/ 밖으로 나가야 한다, 예외를 만드는 게 아니라"를 그대로 적용 |
| **§5** 모든 임계값은 toml | score threshold 등 | `[lesion_model]` 섹션 신설: `enabled`, `score_threshold`, `nms_radius_mm`, `model_path`, `model_sha256` |
| **§4** null ≠ zero | 모델 로드 실패 | 병변 리스트를 `[]` 가 아니라 **`None` + `model_unavailable`**. 빈 배열은 "깨끗한 피부"를 뜻하므로 섞이면 안 된다 |
| **§7** 과설계 금지 | 룰/모델 이중 경로 | 추상 인터페이스를 만들지 않는다. `lesion_model.enabled` 플래그 하나로 분기, 룰 기반은 fallback 으로 남긴다 |
| **§8** `model/` 은 Alchera FaceSDK 폴더 | 이름 충돌 | 신규 가중치는 `assets/lesion/`. `model/` 은 건드리지 않는다 |
| **§10** `data/store/` 불변 | 라벨 저장 | `data/labels/` 로 분리 |

`reprocess.py` 의 `algo_version` + `config_hash` 규약은 유지된다 — 모델 버전과 가중치
해시를 `algo_version` 에 넣으면 **"모델을 바꿨을 때 판정이 뒤집힌 이미지 수"를 기존 도구로
그대로 잴 수 있다.**

**`core/` 6개 파일은 한 줄도 바뀌지 않는다.** 전처리·마스킹·품질 게이트·mm 크기 산출은 그대로 재사용된다.
