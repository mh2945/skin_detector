# CONTRACT — 계층 규칙 (협상 불가)

이 문서의 규칙은 **취향이 아니라 비용 계산의 결과**다. 하나씩 어겨도 당장은 돌아가지만,
모바일 포팅 시점이나 튜닝 100회째에 값을 치른다. `test/test_contract.py` 가 1·5·9번을
AST 로 강제한다 — 문서에만 적어두면 반드시 새어 나가기 때문이다.

---

## 1. `core/` 는 `numpy` + stdlib 만 import 한다

`cv2` · `mediapipe` · `PIL` · `fastapi` 금지.

**이유는 두 가지다.** ① `core/` 는 그대로 C++ 로 옮겨 Android/iOS 공유 코어가 된다.
의존성이 하나 붙을 때마다 포팅 대상이 오염된다. ② 분석 로직을 이미지·카메라·네트워크
없이 단위 테스트할 수 있다 — 실제로 `test/` 는 셀피 한 장 없이 86개를 돌린다.

`cv2` 가 필요해지면 **그 기능이 `core/` 밖으로 나가야 한다**, 예외를 만드는 게 아니라.

> sample2 가 `Analysis/`·`Alerts/`·`Logging/`·`Config/` 를 net8.0 소스 링크로 강제했던 것의
> Python 등가물이다.

## 2. `core/` 함수는 numpy 배열과 dataclass 만 주고받는다

파일 경로 없음, I/O 없음, 전역 상태 없음. 설정은 `Config` dataclass 로 주입한다.

## 3. `core/` 내부 좌표는 전부 정규 프레임이다 — 768×768, IPD = 320

원본 좌표 ↔ 정규 프레임 변환은 **`face.py` 한 곳에서 한 번만** 일어난다.
원본 좌표는 render/report 만 쓰고, 역변환은 `pipeline.lesions_to_original()` 하나뿐이다.

> sample2 의 교훈을 그대로 옮긴 것이다: *"box/landmark 좌표는 분석 이미지(720×1280) 기준 —
> 캡처 원본 좌표로 오버레이를 그리면 어긋난다."* 좌표계가 둘인데 규약이 없으면
> 언젠가 반드시 섞인다.

## 4. null ≠ zero

측정하지 못한 값은 `None` / `NaN` 이고 **명시적 사유 코드가 붙는다.** `0.0` 이 아니다.

`0` 을 반환하면 **"측정 못 함"이 "아주 정상"으로 둔갑한다.** 이마가 앞머리에 가려졌는데
점수 0(=매우 깨끗)이 나가면 사용자는 그 부위를 안심하고 넘긴다.

UI 도 이 규칙을 지킨다 — 웹 결과 화면은 `null` 부위를 **"측정 못 함 + 이유"** 로 표시한다.

## 5. 모든 임계값은 `config/default.toml` 에 있다

코드에 매직 넘버 금지. `core/config.py` 의 dataclass 기본값은 toml 의 **사본**이고,
둘이 어긋나면 테스트가 깨진다. 오타 난 키는 조용히 무시되지 않고 `ValueError` 가 된다 —
설정을 고쳤는데 안 먹는 상황이 한 번이라도 생기면 그 뒤 모든 튜닝 결과를 믿을 수 없다.

## 6. `core/` 는 C++ 로 옮겨쓸 수 있는 스타일로 쓴다

반복문에 1:1 대응되는 벡터 연산만 쓴다. fancy indexing 곡예 금지.
FFT 대신 누적합 박스 필터를 고른 것도 이 규칙 때문이다.

## 7. 과설계 금지

추상 베이스 클래스 · 플러그인 레지스트리 · 의존성 주입 프레임워크를 만들지 않는다.
구현이 하나뿐인 인터페이스를 만들지 않는다.

> **PoC 의 목적은 답을 얻는 것이지 확장성이 아니다.**

## 8. `model/` 의 Alchera FaceSDK DLL·모델은 쓰지 않는다

그 SDK 에는 피부 관련 기능이 전혀 없다(`skin|wrinkle|acne|pore|pigment|derma` 스캔 0건).
쓰든 안 쓰든 붉은기 로직은 신규 구현이므로 배제해도 잃는 것이 없다.
`model/` 폴더는 삭제하지 않고 그대로 두되, 여기에 배선하지 않는다.

## 9. `web/` 는 `pipeline` 만 호출한다

`core/` 를 직접 import 하지 않는다. 웹이 코어를 우회해 직접 조립하기 시작하면
그 로직은 모바일 포팅 때 **통째로 사라진다.** 웹은 얇은 껍데기여야 한다.

사유 코드도 enum 이 아니라 **문자열**로 다룬다 — JSON 이 실어 나르는 형태 그대로.

## 10. `data/store/` 의 원본과 `capture.json` 은 쓰기 전용이다

한 번 쓴 뒤 수정·삭제하지 않는다. 파생물은 전부 `results/` 아래로 간다.

이것이 "지속적 데이터 확보로 고도화 가능한 구조"의 전부다. 원본이 불변이면
알고리즘을 몇 번을 고쳐도 과거 전량을 다시 채점할 수 있고, 결과에 박힌
`algo_version` + `config_hash` 가 어떤 설정에서 나온 숫자인지 말해 준다.

## 부수 규약

**좌/우는 피사체 기준이다.** MediaPipe 의 left/right 는 피사체의 좌우이고,
정면 사진에서 피사체의 오른쪽은 **이미지의 왼쪽(작은 x)** 에 나타난다.
`RegionId.CHEEK_R` = 피사체의 오른쪽 볼 = 이미지 왼쪽.
이 규약은 `core/mask.py` 한 곳에서만 정한다 — 확인된 사실이지 추측이 아니다.

**게이트는 먼저 걸리는 것이 이긴다.** 뒤 조건은 평가조차 하지 않는다.
순서 자체가 설계다: 근본 원인(얼굴이 없다)이 파생 증상(흐리다)보다 먼저 보고돼야
사용자에게 줄 안내 문장이 맞아떨어진다.

**출력 0~100 은 물리량이 아니다.** 순서형 편의 척도이고, 그래서 JSON 필드명이
`score_ordinal_0_100` 이다. 물리적으로 의미 있는 값은 `d`(log₁₀ 비율)와 면적 비율뿐이다.
