# VALIDATION — 검증 방법론과 결과

> **이 문서가 증명할 수 있는 것과 없는 것을 먼저 못 박는다.**
>
> 컬러차트를 쓰지 않기로 확정했으므로 여기서 증명 가능한 것은
> **"조명이 바뀌어도 값이 흔들리지 않는다"(재현성)까지**이고,
> **"그 값이 실제 피부 상태와 맞다"(정확도)는 증명 대상이 아니다.**
>
> 재현성만으로 go/no-go 는 충분히 나온다 — 안 흔들리는 게 먼저이고,
> 안 흔들리면 정확도는 논의 대상도 아니다. 이 구분을 혼동하면 결과가 과대 해석된다.

---

## 0. 촬영 규약 — 여기서 아끼면 전부 무의미해진다

**경로가 둘이고 섞으면 안 된다.**

| 경로 | 용도 | 색 통제 |
|---|---|---|
| **A. 브라우저 캡처** | 일반 사용 · 데이터 수집 | **WB/ISO/토치 제어 불가** |
| **B. 카메라앱 → 업로드** | **검증 전량** · 고품질 측정 | 아래 규약대로 수동 고정 |

> **검증 데이터는 전부 경로 B 로 찍는다.** 브라우저 캡처로 Phase 1 을 돌리면
> **색 통제 실패와 알고리즘 실패를 구분할 수 없다.**
> `validate.py` 는 기본적으로 `capture_path == "upload"` 만 읽는다.

### 경로 B 설정 (iOS: Halide / ProCam, Android: Open Camera)

| 항목 | 값 |
|---|---|
| WB | **켈빈 수동 고정** — 조명 조건마다 값을 정하고 세션 내내 유지 |
| ISO | **수동 고정, 가능한 최저**(100~200) |
| 셔터 | 수동 고정 (거치 촬영이므로 손떨림 여유 있음) |
| 포맷 | **HEIC 또는 최고품질 JPEG** |
| HDR · 야간모드 · 뷰티보정 | **전부 OFF** |
| 플래시 | **토치(연속광)** — 사전 발광 측광 변동 없음 |
| 거치 | **삼각대/거치대 필수** |

**플래시 on/off 쌍**: ISO·셔터·WB 를 고정한 채 **토치만 토글**해 연속 2장.
이 3개가 고정돼야 차분에서 주변광이 상쇄된다.

**파일명이 유일한 진실이다.** 수동 앱은 채널별 WB 게인을 EXIF 에 온전히 남기지 않는다.

```
<세션>_<조명>_<wb켈빈>_<iso>_<torch|noflash>_<n>.heic
예)  s01_window_5500_100_torch_1.heic
```

파싱에 실패하면 `analyze.py --ingest` 가 경고한다. **경고를 무시하고 검증에 쓰면 데이터가 오염된다.**

### 세션 구성

조명 4종(창가 주광 / 텅스텐·LED / 어두운 실내 / 정면 토치) × {torch, noflash} × 반복 2장
= **16장/세션**. 여러 세션·여러 날 반복한다.

피험자가 1인이고 컬러차트도 없으므로 **조건 다양성이 유일한 통계력의 출처다.**

**촬영 10분 전부터 안정**(운동·음주·온도·세안). 한 세션은 짧게 끝내고
**조명 순서를 세션마다 셔플**한다 — 혈관운동 변동이 특정 조명에 계통적으로 실리지 않게.

평가자 3명이 **시스템 출력을 보지 않고** 독립적으로 매긴다(앵커링 방지).

```

트러블 : 일치율 69.0% / NIR 71.0% / kappa +0.11  n=200  <- NIR 대비 여유 부족
```

두 번째 줄이 함정의 모습이다 — 일치율 69% 는 그럴듯해 보이지만 **아무것도 안 하는 모델(71%)보다
낮다.** κ 0.11 이 그 사실을 드러낸다.

## 2. Phase 1 관문 — 조명 간 안정성 (ICC)

```bash
python scripts/validate.py stability
```

같은 얼굴을 4개 이상 조명 조건에서 몇 분 내 촬영. 표정 동일, 화장 변화 없음.
**생리는 거의 불변, 조명만 변했다.** 지표: 부위별 조건 간 **ICC(2,1)**.

비교표: **{raw a\*, Δa\*, raw e, ERI}**

> **핵심은 raw 대비 정규화의 차이다.** `ICC(ERI) ≫ ICC(raw a*)` 이면
> 자기참조가 실제로 일하고 있다는 뜻이다. **이 한 쌍의 숫자가 정보량이 가장 크다.**

> **주의 — 계획서에서 정정된 부분**: 부위별 기준선(`μ_r`)은 부위마다 **상수** 오프셋이므로
> **부위별 ICC 를 바꾸지 않는다.** `μ_r` 이 개선하는 것은 ICC 가 아니라 §1 의 판정 정확도다.
> 두 지표를 혼동하면 "부위별 기준선이 효과 없다"는 잘못된 결론에 도달한다.

**Exit = 프로젝트 전체의 go/no-go.**
> 아무것도 ICC 0.5 를 못 넘으면 그 위에 아무것도 짓지 말고 멈춰서 ROADMAP L1/L4 를 재검토한다.

**결과**: _미측정_

## 3. 합성 홍반 주입 / 복원

```bash
python scripts/validate.py synth
```

> **함정**: 붉은 원을 알파 블렌딩하지 말 것. 비물리적이고 검출기를 실제보다 좋아 보이게 만든다.

**물리적으로 올바른 주입**: 로그 밀도 공간에서 헤모글로빈 방향으로 `D' = D + Δ·v_h`.
`v_h` 는 흡광계수 CSV + 진피 광로장 가중에서 나온다(COLOR_SCIENCE §3).

측정: ① 복원 Δ vs 참 Δ **선형성(기울기·R²)**, ② Δ 에 대한 recall 곡선 → 최소 검출 가능 홍반,
③ 국소화 오차(mm), ④ 부위 귀속 정확도.

- **결정타**: 같은 피험자의 **서로 다른 조명 사진에 동일 Δ 를 주입 → 복원값이 조명에 걸쳐
  일정한가?** §2 와 §3 을 결합한, 라벨 없이 얻을 수 있는 가장 강한 증거다.

**합성 데이터 결과 (실사진 아님)**: 기울기 = 이론값 0.447 의 15% 이내, **R² ≥ 0.99**.
조명 3종(중립 / 텅스텐+어두움 / 그늘+밝음)에 걸친 복원값 편차 **< 0.004**.

## 4. 반복 촬영 노이즈 플로어 — 모든 해석의 기준자

같은 조명에서 2초 간격 2장. 여기서의 차이가 **환원 불가능한 측정 노이즈**다.
> 조명 간 변동 ≈ 반복 촬영 변동이면 정규화가 완벽한 것이다.

**반드시 거치 촬영한다.** 손으로 들면 2초 사이에도 각도·거리가 변하고, 정규 워프가 대부분
흡수하지만 완전하진 않다 → **"환원 불가 노이즈"가 과대평가된다.**
기준자가 부풀면 **정규화 성능이 실제보다 좋아 보인다.**

**결과**: _미측정_

## 5. 좌우 대칭 — 핵심은 비대칭이 아니라 상관관계

생리적 홍조는 대략 대칭이고 **조명 아티팩트는 강하게 비대칭**이다(측면 창광).
`|score_L − score_R|` 가 **조명 구배 지표(`illumination_check`)와 상관되는지** 본다.
상관되면 정규화가 조명을 새고 있는 것이다.

**결과**: _미측정_

## 8. 인간 순위 상관

평가자 2~3명이 얼굴 20장을 "붉어 보이는 정도"로 순위 → Spearman ρ, **인간 간 ρ 를 천장으로**.
§1 의 평가 세션에서 같이 받는다.

> **§1 일치율과 역할이 다르다.** 일치율은 합격/불합격 지표이고 이산 등급을 본다.
> 순위 상관은 연속 점수가 단조로운지 보는 보조 진단이다.
> **등급 일치율은 높은데 순위 상관이 낮다면 경계 근처에서만 맞히고 있다는 뜻이다** —
> 임계값 운이 좋은 것이지 측정이 좋은 게 아니다.

> **기대치 보정**: Logger 2020 은 정성껏 만든 Δa\* 방법으로도 임상의 점수와
> **Rs = 0.30~0.37** 밖에 못 얻었다 — 관찰자 간 재현성 R²=0.82 였는데도.
> **ρ ≈ 0.5 면 잘하는 것이고 0.9 는 비현실적이다.** 미리 공유해 "겨우 0.5?" 반응을 방지한다.

**결과**: _미측정_

## 9. 재처리 검증 — 목표 3의 실증

```bash
python scripts/reprocess.py --all
python scripts/reprocess.py --list
python scripts/reprocess.py --compare v0.1.0_ed33b1 v0.1.0_<새해시>
```

알고리즘이나 `config/default.toml` 을 고친 뒤 과거 전량을 다시 채점한다.
원본과 `capture.json` 은 손대지 않으므로 몇 번을 돌려도 안전하고,
결과는 버전별로 **나란히 쌓인다.**

`--compare` 는 부위별 평균 점수 변화와 **붉은기 판정이 뒤집힌 이미지 수**를 보여준다.
후자가 크게 움직이면 §1 일치율을 다시 재야 한다.
