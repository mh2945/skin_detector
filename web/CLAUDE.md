# web/ — 목표 2 의 실체

**"촬영부터 결과까지 상세한 안내"가 이 디렉터리다.** 부가 기능이 아니라 성능의 일부다 —
촬영 안내가 `docs/LIMITS.md` §3 한계의 절반(혼합 광원·과노출·가림·흐림)을 **캡처 단계에서
제거**해 목표 1의 일치율을 올린다.

## 절대 규칙

1. **`pipeline` 만 호출한다. `core/` 를 직접 import 하지 않는다.**
   `test/test_contract.py` 가 AST 로 강제한다. 웹이 코어를 우회해 직접 조립하기 시작하면
   그 로직은 **모바일 포팅 때 통째로 사라진다.** 웹은 얇은 껍데기여야 한다.
2. **`127.0.0.1` 바인딩 고정.** 얼굴 사진은 생체인식정보일 수 있다. 이미지는 이 컴퓨터
   밖으로 나가지 않는다.
3. **사유 코드는 enum 이 아니라 문자열로 다룬다** — JSON 이 실어 나르는 형태 그대로.

## 구성

```
server.py          FastAPI. GUIDANCE 표 + humanize() + 엔드포인트 4개
static/index.html  5단계 흐름의 마크업
static/app.js      캡처(경로 A) / 업로드(경로 B) / 결과 렌더
static/style.css
```

| 엔드포인트 | 하는 일 |
|---|---|
| `GET /` | 정적 페이지 |
| `GET /api/health` | 모델·설정 로드 상태 |
| `POST /api/analyze` | 업로드 → store 편입 → `pipeline.analyze()` → `humanize()` |
| `POST /api/feedback` | 맞음/과검출/놓침 → `feedback.json` append |

## 5단계 흐름

```
[1] 촬영 안내 → [2] 캡처 → [3] 품질 판정 → [4] 결과 → [5] 피드백
```

**[3] 이 이 UI 의 핵심이다.** 혼합 광원·과노출·앞머리 가림·깊은 그림자·HDR 은
**알고리즘으로 못 고치고 재촬영으로만 고쳐진다.**

## `GUIDANCE` 표가 자산이다

`ReasonCode` 문자열 → `{title, how, retake}` 매핑. 각 사유마다 **무엇이 잘못됐고 어떻게
다시 찍으라**는 문장이 붙는다.

```python
"non_uniform_illumination": {
    "title": "한쪽에서만 빛이 들어옵니다",
    "how": "창을 마주 보거나 조명을 정면에 두고 다시 찍어주세요. "
           "측면광은 그림자를 붉은기로 오인하게 만듭니다.",
    "retake": "yes"},
```

> **문구는 코드가 아니라 자산이다.** 모바일 포팅 때 이 표와 결과 화면 구성은 **그대로
> 옮겨간다** — 웹에서 실제 사용자에게 검증된 문장이 모바일에서도 맞다.

새 `ReasonCode` 를 `core/` 에 추가하면 **여기에도 문장을 추가한다.** 빠지면 사용자는
왜 실패했는지 모른 채 같은 실수를 반복한다.

## 미측정은 0 이 아니다

`null` 인 부위는 **"측정 못 함 + 이유"** 로 표시한다. 0점(=매우 깨끗)으로 그리면
`docs/CONTRACT.md` 4번이 무의미해진다 — 사용자는 가려진 부위를 안심하고 넘긴다.

## 결과 화면의 "근거"

점수만 주면 신뢰가 생기지 않는다. 부위별 `d` 분포 · `coverage` ·
`anatomical_prior_calibrated` · 품질 플래그를 **접히는 상세 영역에 그대로 노출**한다.

## 두 캡처 경로를 섞지 않는다

| 경로 | 용도 | 색 통제 |
|---|---|---|
| A. 브라우저 캡처 | 일반 사용 · 데이터 수집 | **WB/ISO/토치 제어 불가** |
| B. 카메라앱 → 업로드 | **검증 전량** · 고품질 측정 | 수동 고정 |

결과 JSON 의 `capture_path` 로 항상 구분 가능하게 둔다.
**경로 A 데이터로 성능을 주장하지 않는다** — 색 통제 실패와 알고리즘 실패를 구분할 수 없다.

브라우저 캡처는 기기·브라우저마다 해상도가 다르다. `{width:{ideal:3840}}` 을 요청하되
**실제로 받은 해상도를 확인**해 `native_ipd_px < 150` 이면 병변 검출을 끄고 미만성만 보고한다.
