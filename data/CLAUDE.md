# data/ — 불변 원시 레이어 (목표 3)

**"지속적 데이터 확보로 고도화 가능한 구조"의 전부가 여기다.**
프레임워크가 아니라 **규약 두 개**다 — 원본이 불변이고, 결과에 버전이 박힌다.

```
data/
├─ spectra/hb_melanin_extinction.csv   유일한 외부 데이터 파일 (커밋 대상)
├─ incoming/                           편입 대기 (gitignore)
├─ store/                              ★ 불변 원시 레이어 (gitignore)
└─ panel_ratings.csv                   평가자 등급 (gitignore)
```

## `store/` 구조

```
data/store/<capture_id>/
├─ original.<ext>       원본 그대로. 리사이즈·재인코딩·수정·삭제 금지
├─ capture.json         촬영 사실. 수정·삭제 금지
├─ feedback.json        결과 화면 피드백 append
└─ results/
   ├─ v0.1.0_ed33b1.json   같은 원본, 여러 알고리즘 버전이 나란히 쌓인다
   └─ v0.2.0_71be03.json
```

**`original.*` 와 `capture.json` 은 쓰기 전용이다.** 한 번 쓴 뒤 수정·삭제하지 않는다.
파생물은 전부 `results/` 아래로 간다.

원본이 불변이면 알고리즘을 몇 번을 고쳐도 **과거 전량을 다시 채점할 수 있고**, 결과에 박힌
`algo_version` + `config_hash` 가 **어떤 설정에서 나온 숫자인지** 말해 준다.
그게 없으면 수백 번의 튜닝 이력이 통째로 무의미해진다.

`capture_id` 는 **내용 해시 기반**이라 같은 파일을 두 번 편입해도 중복이 생기지 않는다.

## 파일명이 유일한 촬영 메타다

수동 카메라 앱은 **채널별 WB 게인을 EXIF 에 온전히 남기지 않는다.** ISO·셔터·초점거리는
읽히지만 게인은 대개 못 읽는다. 그래서 사람이 파일명으로 적는다.

```
<세션>_<조명>_<wb켈빈>_<iso>_<torch|noflash>_<n>.heic
s01_window_5500_100_torch_1.heic
```

**파싱 실패하면 `null` 로 들어가고 `--ingest` 는 경고만 한다.**
경고를 무시하고 검증에 쓰면 데이터가 조용히 오염된다.

`capture.json` 의 `awb_gains` 가 `null` 인 것은 정상이다 — 필드를 미리 만들어 뒀고,
모바일에서 실제 적용된 게인을 채우게 된다.

## 두 캡처 경로를 섞지 않는다

`capture_path` 가 `"browser"` 인지 `"upload"` 인지로 두 모집단을 **절대 섞지 않는다.**
`validate.py` 는 기본적으로 `upload`(경로 B)만 읽는다.
**경로 A 데이터로 성능을 주장하지 않는다** — 색 통제 실패와 알고리즘 실패를 구분할 수 없다.

## 피드백은 약한 라벨이다

`{verdict, region, ts, algo_version}` 이 한 줄씩 쌓인다. 임계값 보정과 **실패 사례 수집**에는
바로 쓰이지만, **사용자는 틀렸을 때 더 자주 누른다(부정 편향).**
**피드백 비율을 정확도로 읽으면 안 된다.**

지도학습용 클릭 라벨로는 부족하다. 그 시점이 오면 `scripts/label.py` 를 추가한다 —
**지금 만들지 않는다.**

## 개인정보

**얼굴 사진은 생체인식정보에 해당할 수 있다.**

- `store/` · `incoming/` · `panel_ratings.csv` 는 **gitignore 대상이다.** 커밋하지 않는다.
- 웹 서버는 `127.0.0.1` 을 벗어나지 않는다.
- `capture.json` 의 `subject_id` · `consent` 는 지금 `self` / `n/a` 다.
  **본인 외 데이터가 들어오는 순간 동의·보관·파기 정책이 선행 조건**이고, 그 전까지
  이 필드를 다른 값으로 채우지 않는다.

## `spectra/` 는 손대지 않는다

`hb_melanin_extinction.csv` 는 **유일하게 허용된 외부 데이터 파일**이고
`test_contract.py` 가 그 사실을 강제한다. 헤더에 출처가 정직하게 적혀 있다 —
HbO2 는 문헌 구조의 가우시안 합 근사이고 멜라닌은 Jacques 멱법칙이다.
**전사(轉寫)가 아니라 근사라는 사실을 지운 채 인용하지 않는다.**
